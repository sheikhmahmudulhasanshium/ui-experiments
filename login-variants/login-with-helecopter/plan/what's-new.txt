--------------------------------------------------------------------------------
1. PROJECT OVERVIEW & CORE CONCEPT
--------------------------------------------------------------------------------
A high-impact, interactive airborne login component where a vector SVG helicopter 
flies into the viewport from the right, settles in a hover, and unrolls an 
underslung canvas document holding a secure pilot login form.

The entire UI (flight entrance, hover vibration, unrolling canvas reveal, 
authenticated departure to the left, and catastrophic spiral crash on failure) 
is controlled purely through HTML form state mechanics (<input type="radio"> + 
CSS :checked pseudo-class selectors + CSS keyframe animations).

--------------------------------------------------------------------------------
2. CHRONOLOGICAL EVOLUTION & PROBLEM-SOLVING LOG
--------------------------------------------------------------------------------

Phase 1: Aesthetic Cleanup
  - Issue: Distracting pilot silhouette and an orange accent stripe inside the cockpit.
  - Fix: Completely removed the pilot SVG elements and the orange stripe cutting 
    across the cockpit windshield/door for a modern, sleek canopy glass finish.

Phase 2: Cargo Rigging & Ladder
  - Issue: Narrow rescue ladder was insufficient for carrying cargo/loads.
  - Fix: Replaced with a wide 2-rope heavy-duty cargo suspension harness spanning 
    between front and rear skid legs, equipped with spreader rungs and industrial 
    clevis lifting hooks at the bottom.

Phase 3: The Rolling Billboard Canvas
  - Issue: Needed a dynamic way to reveal content held by the cargo hooks.
  - Fix: Connected the hooks to a rigid spreader beam holding a canvas banner. 
    The banner unrolls downward with an elastic settling bounce, while a weighted 
    bottom roller rod physically descends and caps off the lower edge.

Phase 4: Login Form Integration & Flight Mechanics
  - Transformation: Scaled down the helicopter and repurposed the billboard 
    into a functional Pilot Login Form (Callsign + Security Code).
  - State Logic:
      1. Default / Reset: Flies in from 2x viewport right (+160vw) to center, 
         stabilizes, and unrolls the login sheet.
      2. Authenticate & Depart (Success): Turns green, gathers lift, pitches 
         forward, and flies off-screen to the left (-170vw).
      3. Simulate Wrong Password (Fail): Strobe flashes red, turbine emits 
         smoke particles, engine stalls, and the helicopter spirals down into 
         a full vertical crash (+130vh).

Phase 5: Blade Speed & Visual Tuning
  - Issue: Rotor blades were spinning at 0.05s, which looked like a static blur.
  - Fix: Slowed the main rotor to 0.42s and the tail rotor to 0.22s, allowing 
    individual blades and yellow high-vis tips to be visibly tracked.
  - Tail Rotor Fix: Removed the tilted perspective transform `scale(0.28, 1)` 
    so the tail rotor spins flat on a 2D circle like a 4-petal flower/pinwheel.
  - Landing Gear Color: Unified the front landing gear runner to match the dark 
    slate finish (#1e293b) of the rear landing gear.

Phase 6: Structural Modularity (Section Isolation)
  - Refactored the entire codebase into isolated, modular sections, each with its 
    own dedicated preceding <style> tag:
      - Global & Base: :root variables, reset, viewport lock, keyframes
      - .navbar-section: Floating mission control state trigger bar
      - .helecopter-section: Scaled SVG fuselage, mast, rotors, skids, smoke
      - .ladder-section: Connected suspension cables, rungs, and hooks
      - .form-section: Top beam, unrolling card, input fields, buttons, roller

Phase 7: Alignment & Connection Fixes
  - Issue: The ladder was disconnected from the skids above and the form below.
  - Fix: Re-mapped the helicopter SVG and ladder SVG to a 1:1 pixel scale (320px wide). 
    Locked the skid attachment clamps, suspension cables, and form eyelet rings 
    to the exact same horizontal coordinates: x = 120px and x = 200px. 
    Removed inline SVG font descender baseline gaps using `display: block; line-height: 0;`.

Phase 8: Mobile Engine & Viewport Hardening
  - Issue 1 (Navbar Disappearing):
      * Root Cause A: Centering with `transform: translateX(-50%)` caused mobile WebKit 
        to drop the fixed layer during animations. Fixed by centering with 
        `left: 0; right: 0; margin: 0 auto; width: fit-content;`.
      * Root Cause B: 160vw translation expanded mobile document width and caused 
        horizontal scrolling. Fixed by enclosing the rig in an `overflow: hidden` 
        clipping container (.stage-viewport) and locking `body` with `position: fixed; inset: 0`.
  - Issue 2 (Reset / Reload Failure):
      * Root Cause: Mobile browsers cached radio states on reload, and animations 
        did not restart because they were bound to base styles. Fixed by adding 
        `autocomplete="off"` to radio inputs and binding all playback strictly to 
        `#state-flyin:checked`.

Phase 9: Standards Compliance & Input Overflow Fix
  - Issue 1 (Linter Warning): Nonstandard `-webkit-appearance: none;` flagged by linter.
    Fix: Replaced with standard W3C `appearance: none;`.
  - Issue 2 (Input Box Right Border Overflow): Setting `appearance: none;` caused 
    browsers to calculate input width as `content-box`, causing `width: 100% + padding` 
    to punch through the right border.
    Fix: Enforced `box-sizing: border-box; display: block; width: 100%;` across all 
    form elements and set a 16px internal gutter for symmetric border alignment.
